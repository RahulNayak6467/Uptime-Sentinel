# V12 — Multi-Region Monitoring

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Not started

### Goal and scope

Run checks from multiple geographic regions and distinguish full outages from
regional degradation.

### Core features

- [ ] Regions and region-linked check results.
- [ ] Region selection per monitor and separately deployed regional workers.
- [ ] Global `UP`, `DOWN`, and `DEGRADED` aggregation.
- [ ] Regional latency views, partial-outage detection, and regional alerts.

### Supporting work

- [ ] Region health logic, worker deployment, and failure-tolerant aggregation.
- [ ] Per-region detail cards for the extended check types, deferred from V7 and
  currently shown blurred as "coming soon" in the monitor detail designs:
  - TCP: **port reachability by region** and **connect-results-by-region heatmap**
    (the single-region "Connect results" uptime strip ships in V7).
  - DNS: **resolution per probe region**.
  - TLS: **certificate served per region** (per-region fingerprint/handshake match).
  These need the regional workers from this version; the checkers and single-region
  views are built in V7.

### Concepts learned

Distributed workers, network geography, partial failures, health aggregation,
and multi-region deployment.

### Out of scope

Global database replication, active-active API regions, and automatic failover.
