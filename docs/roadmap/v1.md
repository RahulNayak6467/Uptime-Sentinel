# V1 — Endpoint Manager

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Partial

### Goal and scope

Persist monitors and their check history, support CRUD, and allow checks to be
run manually. This version remains single-user even though `user_id` may be
nullable in preparation for V2.

### Core features

- [~] `monitors` table with URL, name, scheduling fields, active state, latest
  status snapshot, timestamps, and nullable `user_id`.
- [x] `checks` table linked to `monitor_id` with status, latency, status code,
  error, and check time.
- [x] Create, list, and retrieve monitors.
- [ ] Update a monitor with `PATCH /monitors/:id`.
- [ ] Delete a monitor and cascade its checks.
- [x] Manually check a monitor and retrieve its check history.

### Supporting work

- [x] PostgreSQL pool, UUID keys, foreign keys, cascading deletes, parameterized
  queries, validation, environment validation, and not-found handling.
- [ ] Default check-history limit of 50 with a validated configurable limit.
- [ ] Add and consistently run ESLint and Prettier.

### Concepts learned

PostgreSQL with `pg`, pooling, parameterized SQL, relational modeling,
one-to-many relationships, foreign keys, cascades, UUIDs, and latest-snapshot
versus historical-data patterns.

### Out of scope

Authentication, user ownership, automatic checks, Redis, workers, and alerts.
