# V15 — Application Observability

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Not started

### Goal and scope

Make the API, scheduler, and workers diagnosable through structured logs, health
signals, error tracking, and queue visibility.

### Core features

- [ ] Pino request, worker, incident, and alert event logs.
- [ ] Correlation IDs and consistent log levels.
- [ ] Sentry error tracking and Bull Board queue visibility.
- [ ] Health checks for API, database, Redis, and workers.
- [ ] Error-rate alerts and log-retention rules.
- [ ] Audit / activity log: append-only, immutable record of user actions
      (monitor created/paused/deleted, alert settings changed) with actor,
      target, action type, timestamp, and metadata. Salvaged from descoped V9;
      single-user personal action history. **Product feature — keep distinct from
      the infra logging above:** audit log records *user actions*, Pino/Sentry
      logs diagnose the *system*. Only depends on existing CRUD, so it may also be
      done as a standalone slice in any earlier light week.

### Concepts learned

Structured logging, correlation, health/readiness checks, error tracking,
operational event design, and log retention.

### Out of scope

Full Prometheus/Grafana/Loki/OpenTelemetry deployment, which belongs to V18.
