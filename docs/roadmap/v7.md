# V7 — Custom Rules and Extended Check Types

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Not started

### Goal and scope

Let users define what healthy means and extend monitoring from HTTP responses to
SSL certificates, DNS records, and TCP port reachability.

### Core features

- [ ] Expected status codes, custom timeout, keyword checks, failure threshold,
  and recovery threshold.
- [ ] Add a configurable response-time alert threshold in milliseconds during
  the next monitor-table migration, expose it in the monitor form, and replace
  the individual-monitor chart's hardcoded `1000ms` threshold. Keep this value
  separate from the request timeout: it marks a successful response as slow
  rather than marking the request as failed.
- [ ] Consecutive success/failure counters and threshold-aware state machine.
- [ ] SSL expiry checks and configurable expiry alerts.
- [ ] DNS record snapshots, change detection, and alerts.
- [ ] **Suggestion (off-roadmap, accepted):** TCP host/port reachability checks
  with configurable connection timeouts.
- [ ] **Suggestion (off-roadmap, accepted):** authenticated HTTP checks using
  custom headers and encrypted static credentials. Implement this after the
  DNS, TCP, and TLS check types; multi-step login, OAuth, and automatic token
  refresh remain out of scope.
- [ ] Cursor (keyset) pagination for the high-volume log lists: the all-monitors
  email-alerts list and the monitor check-logs list (all-monitors and
  per-monitor). These are append-only time series that grow unbounded; offset
  pagination stays on V6's bounded, per-user numbered-page views (monitors table,
  7-day alerts). Other high-volume lists remain scheduled for V11.

### Supporting work

- [ ] Complete the deferred frontend naming cleanup documented in
  [`v7-cleanup.md`](v7-cleanup.md).
- [ ] Zod rule configuration, partial-update semantics, and sensible defaults.
- [ ] Rule evaluation in workers.
- [ ] Node `tls`, `dns`, and `net` integrations with stored SSL/DNS snapshots.
- [ ] Keyset cursor encoding/decoding, a stable total ordering (e.g. a
  `(created_at, id)` tiebreak), and a next/prev cursor contract.
- [ ] `tlsFetcher` result envelope: wrap the checker in a Promise that returns a
  single consistent shape (`status`, `certificate`, `error`) from every path —
  `secureConnect` success, the `error`/timeout handler, and the "no certificate
  presented" (`x509Certificate` undefined) guard. Deferred while the checker is
  still a console.log prototype; needed once a caller consumes the result.
- [ ] Cipher-order config finding: the 4th "Protocol & cipher scan" row (does the
  server enforce its own cipher preference). Needs a two-connection probe —
  connect with the `ciphers` list in opposite orders (`maxVersion: TLSv1.2`) and
  compare `socket.getCipher().name`; same pick both times → Pass, follows client
  order → Warn; TLS 1.3-only → Pass/N-A. Deferred to after the other TLS features
  (high effort, low payoff — moot on TLS 1.3).

### Concepts learned

Configurable business rules, threshold state machines, PATCH semantics, TLS
certificates, expiry detection, DNS resolution, change detection, TCP sockets,
encrypted secret storage, header redaction, and keyset/cursor pagination for
unbounded time-series lists.

### Out of scope

Public pages, S3, collaborative workspaces, regional monitoring, and billing.
