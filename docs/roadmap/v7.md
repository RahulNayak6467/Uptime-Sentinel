# V7 — Custom Rules and Extended Check Types

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Not started

### Goal and scope

Let users define what healthy means and extend monitoring from HTTP responses to
SSL certificates and DNS records.

### Core features

- [ ] Expected status codes, custom timeout, keyword checks, failure threshold,
  and recovery threshold.
- [ ] Consecutive success/failure counters and threshold-aware state machine.
- [ ] SSL expiry checks and configurable expiry alerts.
- [ ] DNS record snapshots, change detection, and alerts.
- [ ] Cursor (keyset) pagination for the high-volume log lists: the all-monitors
  email-alerts list and the monitor check-logs list (all-monitors and
  per-monitor). These are append-only time series that grow unbounded; offset
  pagination stays on V6's bounded, per-user numbered-page views (monitors table,
  7-day alerts). Other high-volume lists remain scheduled for V11.

### Supporting work

- [ ] Zod rule configuration, partial-update semantics, and sensible defaults.
- [ ] Rule evaluation in workers.
- [ ] Node `tls` and `dns` integrations with stored SSL/DNS snapshots.
- [ ] Keyset cursor encoding/decoding, a stable total ordering (e.g. a
  `(created_at, id)` tiebreak), and a next/prev cursor contract.

### Concepts learned

Configurable business rules, threshold state machines, PATCH semantics, TLS
certificates, expiry detection, DNS resolution, change detection, and
keyset/cursor pagination for unbounded time-series lists.

### Out of scope

Public pages, S3, collaborative workspaces, regional monitoring, and billing.
