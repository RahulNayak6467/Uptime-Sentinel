# V8 — Public Status Pages, Exports, and S3

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Not started

### Goal and scope

Publish selected monitor health safely and generate downloadable artifacts using
cloud object storage.

### Core features

- [ ] Status pages, monitor membership, CRUD, unique slugs, and public
  `GET /status/:slug`.
- [ ] Maintenance announcements and incident presentation.
- [ ] AWS S3 integration, Puppeteer screenshots, CSV history exports, presigned
  downloads, and background report jobs.

### Supporting work

- [ ] Public-data allowlist, slug validation, and public-route rate limiting.
- [ ] Least-privilege IAM, multipart upload where needed, and old-file cleanup.
- [ ] **Suggestion (off-roadmap, accepted):** user profile picture (avatar)
  upload/remove, stored on S3 alongside report artifacts; shown in the app and on
  emails. Reuses the same S3 + presigned-URL plumbing. Surfaced in Settings →
  Account.
- [ ] **Suggestion (off-roadmap, accepted):** detailed HTTP timing breakdown for
  DNS lookup, TCP connection, TLS handshake, response headers/approximate TTFB,
  response-body download, and total request duration using monotonic clocks and
  lower-level Node/Undici instrumentation where required.

### Concepts learned

Public/protected data boundaries, many-to-many page membership, S3 objects and
keys, IAM, presigned URLs, headless browsers, file generation/streaming, and
background report generation, monotonic timing, and HTTP request-phase
instrumentation.

### Out of scope

Teams, role management, subscriptions, and multi-region checks.
