# V3 — Automatic Monitoring

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Complete, with carried-forward V1/V2 gaps

### Goal and scope

Automatically check active monitors at their configured intervals using an
in-process scheduler while preserving manual checks.

### Carried forward

- [ ] Monitor update and delete.
- [ ] `GET /auth/me`.

### Core features

- [x] Monitor interval, `next_check_at`, and active-state scheduling fields.
- [x] Minute-based `node-cron` scheduler that finds due active monitors.
- [x] Automatic checks, stored history, latest snapshot updates, and next-run
  calculation.
- [x] Pause and resume monitoring.

### Supporting work

- [x] Dedicated scheduler module that reuses the existing check service.
- [x] Per-monitor and scheduler-level error isolation.
- [x] Always advance `next_check_at`, including after a failed check.
- [x] Database pool error handling and scheduler shutdown on termination.

### Concepts learned

Cron scheduling, background work inside an API process, due-time queries,
graceful shutdown, process signals, and failure isolation in loops.

### Out of scope

Distributed scheduling, queues, worker processes, retries, incidents, and
notifications.
