# V10 — Security Hardening and API Versioning

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Not started

### Goal and scope

Protect the monitoring service from abuse and publish a stable, documented V1
API contract.

### Core features

- [ ] SSRF protection for local/private/link-local/cloud-metadata addresses,
  including DNS resolution, DNS-rebinding (validated-IP pinning for the actual
  connection), and redirect revalidation.
- [ ] Route-specific rate limits, Helmet, strict CORS, request-size limits, and
  outbound response-size limits.
- [ ] `/v1` route prefix, OpenAPI specification, Swagger UI, changelog, and
  deprecation policy.
- [ ] Replace Bull Board basic auth with application JWT/RBAC authorization.

#### Abuse-control additions (accepted 2026-08-16, off-roadmap security review)

Added after a security-review discussion once the project moves toward a
**shared/multi-user deploy** (sharing in a college group). These close abuse
vectors that don't exist in single-user mode but become real the moment strangers
can sign up.

- [ ] **Per-user resource quotas** — cap max monitors per user and **enforce a
  minimum check interval**. Prevents one user exhausting the worker/DB/Redis by
  adding thousands of monitors or sub-second intervals (the #1
  monitoring-specific abuse vector once shared). *Enforcement lives in V10;
  performance tuning of the limits stays in V11.*
- [ ] **Dedicated auth brute-force protection** — stricter, dedicated rate limits
  + lockout on the login/auth routes (beyond the generic route rate limits).
- [ ] **Alert-recipient verification** — verify ownership of any alert recipient
  address so the alert system can't be turned into a spam relay. (Lower priority
  if alerts only ever go to the account's own verified email.)

### Supporting work

- [ ] IP-range utilities, redirect limits, security tests, and documented block
  rules.
- [ ] Dependency vulnerability scanning (`npm audit` / Dependabot) — cheap
  supply-chain hygiene against known CVEs in dependencies.
- [ ] Security-event logging (blocked SSRF attempts, failed logins, quota
  rejections) — *overlaps V15; wire into structured logging there.*

> **Already covered — no work needed:** SQL injection is neutralized by design
> (parameterized `pg` queries, no ORM string-building). App-level HTTPS/TLS
> termination + secrets management are security-relevant but owned by **V17**
> (deploy), not duplicated here.

### Concepts learned

SSRF and DNS rebinding risks, private networks, abuse controls, security headers,
API versioning, OpenAPI, documentation, and deprecation.

### Out of scope

Performance tuning, regional deployment, billing, and advanced threat detection.
