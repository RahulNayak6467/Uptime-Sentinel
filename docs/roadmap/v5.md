# V5 — Incidents and Email Alerts

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Not started

### Goal and scope

Turn individual check results into durable downtime incidents and send exactly
one down notification and one recovery notification per incident.

### Core features

- [ ] Incidents and notification-log tables.
- [ ] Incident state machine: open on first qualifying `DOWN`, ignore repeated
  `DOWN`, resolve on recovery, and ignore normal `UP` results.
- [ ] Down and recovery email delivery through Resend.
- [ ] Alert deduplication and monitor incident-history endpoint.
- [ ] Separate BullMQ alert queue handled outside the API server.

### Supporting work

- [ ] Atomic incident transition and notification intent.
- [ ] Delivery retries with success/failure audit records.
- [ ] Down email context and recovery duration calculation.
- [ ] Basic Sentry initialization and global exception capture.

### Concepts learned

State machines, alert deduplication, transactional state transitions,
third-party email delivery, audit logs, retryable notification work, and outage
duration calculation.

### Out of scope

Advanced thresholds, additional alert channels, analytics, public status pages,
and billing.
