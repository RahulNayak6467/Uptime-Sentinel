# V16 — Comprehensive Testing

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Not started

### Goal and scope

Establish production-grade automated coverage across service logic, HTTP APIs,
authentication, ownership, workers, and failure paths.

### Core features

- [ ] **Vitest** + Supertest setup (framework choice locked to Vitest —
  modern TS/ESM default; Jest not used).
- [ ] Service unit tests and route integration tests using an isolated database
  via **Testcontainers** (real ephemeral Postgres, not mocks — see the DB
  integration test harness).
- [ ] Mock outbound HTTP, email, and queue dependencies appropriately.
- [ ] Fixtures/factories, deterministic setup/teardown, and test environment.
- [ ] Auth, ownership, error, retry, and idempotency coverage.
- [ ] Coverage reporting and thresholds.
- [ ] GitHub Actions CI running lint and tests for each pull request.

#### Current-state gap to close (flagged 2026-08-16)

There is **no test framework installed yet** — `package.json` has no
Vitest/Jest/Supertest/Testcontainers and the `test` script is still the default
`echo "no test specified"` placeholder. The existing TLS test files
(`computeStatusTest.ts`, `tlsStateMachineIntegrationTest.ts`, and the other
`*Test.ts` suites) are **hand-rolled assertions run manually**, not a framework.

- [ ] Install Vitest + Supertest + Testcontainers and wire the `test` script.
- [ ] **Migrate the existing hand-rolled `*Test.ts` suites into Vitest** — the
  test *logic* already exists and is green, so this is a port, not a rewrite.
- [ ] This is the single change that moves the project from "has tests" to
  "industry-standard testing."

### Concepts learned

Testing levels, isolation, dependency mocking, fixtures, test databases, CI
quality gates, and meaningful coverage.

### Out of scope

Full deployment automation, large-scale load testing, and synthetic production
testing.
