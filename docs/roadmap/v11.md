# V11 — Scaling and Performance

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Not started

### Goal and scope

Keep queries, storage, scheduling, and dashboards efficient as monitor and check
volumes grow.

### Core features

- [ ] Indexes for monitor ownership/due time and check/incident history.
  Include `incident_updates`: timeline reads filter on `incident_id`, and the
  existing partial unique index `incident_updates_one_lifecycle_note`
  (created in V6 as a correctness constraint, one detected/resolved row per
  incident) should be revisited here for its read-path role.
- [ ] Cursor pagination for high-volume lists.
- [ ] Check retention and nightly cleanup.
- [ ] Hourly/daily aggregate tables and cached dashboard summaries.
- [ ] Batch scheduling, worker-concurrency tuning, N+1 elimination, and slow
  query analysis with `EXPLAIN ANALYZE`.

### Supporting work

- [ ] Slow-query logging, cache invalidation rules, and measured performance
  baselines before optimization.

### Concepts learned

Indexes, query plans, cursor pagination, retention, pre-aggregation, caching,
cache invalidation, batching, and the N+1 problem.

### Out of scope

Multi-region topology, arbitrary sharding, and optimization without evidence.
