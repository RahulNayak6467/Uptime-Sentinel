# V17 — Docker, CI/CD, and Production Deployment

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Not started

### Goal and scope

Run the complete system in containers and deploy it safely through automated
pipelines with production-managed dependencies.

### Core features

- [ ] Multi-stage Dockerfiles for API, worker, and scheduler.
- [ ] Docker Compose for API, workers, scheduler, PostgreSQL, and Redis.
- [ ] CI for lint/test/build and CD on approved main-branch changes.
- [ ] Production hosting, managed PostgreSQL/Redis, HTTPS, and secrets.
- [ ] Automated migrations, health checks, zero-downtime strategy, rollback,
  and production logging.

### Deployment approach — DECIDED 2026-08-16 (IaaS on AWS, Terraform-provisioned)

Dev chose **IaaS over PaaS** (values fewer/deeper projects with good practices
over the quickest path). StatusForge is the **"solid/standard IaaS"** vehicle;
**advanced IaaS** (EKS/K8s, HPA autoscaling, GPU, Step Functions, CloudFront) is
deliberately deferred to the **video-transcoding-pipeline** project so infra
learning isn't redundant. K8s stays out of scope *here* (see below).

**Target AWS stack for StatusForge:**

- **Compute — ECS + Fargate**, three services matching the process topology:
  - API service → desired count = **N** (scalable)
  - Worker service → desired count = **N** (scalable)
  - Scheduler service → desired count = **1** (⚠️ singleton — two instances
    double-enqueue every check)
- **Managed data (not self-hosted):** RDS PostgreSQL + ElastiCache Redis.
- **Registry:** ECR.
- **Networking:** VPC, subnets, security groups.
- **Traffic + HTTPS:** ALB + ACM (certs) + Route 53 (DNS).
- **Secrets:** Secrets Manager / SSM Parameter Store (never baked into images).
- **Logs/metrics:** CloudWatch (ties into V15/V18).
- **Identity:** IAM roles, least-privilege.
- **Everything provisioned as code with Terraform.**

**Operational patterns:** ECS rolling deployments + health-check gate
(zero-downtime); DB migrations as a **one-off pre-deploy ECS task** (not on
container start); graceful `SIGTERM` so workers drain in-flight BullMQ jobs;
image tags by git SHA for exact rollback.

*Good-practice note:* "IaaS" here = IaaS compute + **managed** data. Do NOT
self-host Postgres/Redis on a raw VM — that is more work and less reliable, not
"more proper."

### Concepts learned

Containers, Compose, image optimization, environment parity, CI/CD, secrets,
health checks, migrations during deployment, rollback, and zero downtime.

### Out of scope

Kubernetes, complex service meshes, and multi-cloud orchestration. **(K8s is
intentionally the video-pipeline project's job, not StatusForge's — keep V17 on
ECS/Fargate.)**
