# V2 — Authenticated Dashboard

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Partial

### Goal and scope

Make StatusForge multi-user. Users authenticate with short-lived access tokens
and long-lived refresh tokens, and can access only their own monitors.

### Carried forward

- [ ] Complete monitor update and delete from V1.

### Core features

- [x] Users and refresh-token persistence.
- [x] Registration, login, access/refresh token issuance, refresh, and logout.
- [ ] `GET /auth/me` for the current user.
- [x] Authentication middleware and typed `req.user`.
- [x] Protected monitor routes and ownership checks for read, update, delete,
  manual check, and history operations.

### Supporting work

- [x] bcrypt hashing, unique email constraint, generic credential errors,
  separate signing secrets, startup secret validation, and correct `401`/`403`
  semantics.
- [x] Refresh-token upsert and atomic registration transaction.
- [x] Explicit expired-token and invalid-token handling.

### Concepts learned

Password hashing, JWT anatomy, access versus refresh tokens, token storage and
rotation, authentication middleware, authorization/ownership, transaction
boundaries, and tenant data isolation.

### Out of scope

Scheduled checks, Redis blacklisting, queues, teams/RBAC, and social login.
