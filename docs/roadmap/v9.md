# V9 — Teams and Workspaces

> Part of the [StatusForge roadmap](../../ROADMAP.md). See the index for the full
> version map, current state, and the deferred-work register.

**Status:** Descoped — not building. StatusForge is **single-user by design.**

> **Decision (2026-06-30):** V9 is cut to fit a ~3-4 month build window. Teams,
> workspaces, and RBAC are inherently multi-user and add no reliability or
> correctness value for a single-owner product; cutting them also simplifies V8
> (status pages) and V13 (integrations) into user-owned features. Ownership stays
> scoped directly by `user_id`, kept centralized so a future teams shift would be
> additive rather than a rewrite. This file is preserved (not deleted) so the scope
> and reasoning survive if the decision is ever revisited.
>
> **Salvaged:** the only V9 feature independent of user count — the **audit /
> activity log** — is reframed as a single-user personal action history and moved
> to **V15**. Everything below is retained for reference only and is not being
> built.

### Goal and scope

Support collaborative, tenant-isolated workspaces with explicit roles and
auditable membership changes.

### Core features

- [ ] Workspaces, members, expiring invites, and workspace-owned monitors.
- [ ] Owner, admin, member, and viewer roles.
- [ ] Workspace alert settings and audit logs.
- [ ] Role-aware Bull Board access.

### Supporting work

- [ ] Central RBAC middleware and per-action permission matrix.
- [ ] Owner-protection rules, invite expiry, and multi-tenant isolation tests.

### Concepts learned

RBAC, permission matrices, many-to-many membership, invitations, audit logging,
and multi-tenant boundaries.

### Out of scope

Billing, enterprise identity, custom roles, and cross-workspace sharing.
